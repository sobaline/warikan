# 割り勘精算

旅行や飲み会で「誰がいくら立て替えたか」を入力すると、送金回数が少なくなる精算方法を自動で計算するWebアプリです。URLをLINEに貼るだけで、アプリのインストールなしでみんなで使えます。

公開URL：https://warikan-kohl.vercel.app

## 主な機能

### 精算
- 支払いを入力すると、送金リストを自動で作成（送金回数は「人数−1」回以内）
- 「幹事にまとめる」モード（幹事以外は1回の送金で済む）
- 割り切れない1円は、立て替えた人以外から支払いごとの「くじ」で選んだ人が持つ（特定の人に偏らない）
- 個別金額の入力（食べた分を1人ずつ入れ、残りは均等に割る）
- その場で精算した人、リスト以外の送金、貸し借り、前払い金（集金）の記録
- 送金済みチェック、精算の確定と確定後の変更の警告、精算完了の表示
- 精算結果をLINEにテキストで送る

### 入力
- 外貨対応（自動レートで仮計算し、カード明細の実額に書き換え可能。払った人が損しない）
- 金額の欄で足し算・引き算（「1200+800」、全角数字も可）。円は1円単位
- 時間の自動入力、種類（食事・交通など）の任意入力
- 同じ日付・同じ金額の二重入力の警告
- 入力途中の内容を保持（自動更新・タブ切り替え・ページの読み込み直しでも消えない）

### 家計簿
- 自分が使ったお金（自分の負担分）の合計、日別、種類別
- 自分だけの買い物（精算には影響せず、本人の画面にだけ表示）

### 安全・記録
- メンバーごとの4桁の暗証番号（初回に設定。別の端末では入力が必要。5回まちがえると10分ロック）
- 書き込みは暗証番号でログインした人だけ（データベース側でも制限）
- ログ：誰がいつ何をしたか、変更前→変更後。削除した記録の復元、削除直後の「元に戻す」
- 2人以上が同時に使ったときの対策（保存直前の読み直し、同時編集の上書き確認）

### そのほか
- メモ・チェックリスト（外貨の明細待ちは自動で項目が入る）
- 最近開いたグループの一覧、メンバーの名前変更・追加・削除
- ダークモード（スマホの設定に自動で合わせる）

## 構成

| 役割 | 使っているもの |
| --- | --- |
| 画面 | HTML / CSS / JavaScript（ビルド不要） |
| データ | Supabase（PostgreSQL、東京リージョン） |
| 公開 | Vercel（GitHubへのpushで自動公開） |
| 停止対策 | GitHub Actions（3日ごとにSupabaseへアクセス） |
| 為替レート | Frankfurter API |

```
GitHub（コード） ──自動公開──▶ Vercel（Webサイト）
                                    │ アプリのファイル
                                    ▼
                              利用者のブラウザ ◀──データの読み書き──▶ Supabase
```

## しくみのポイント

- **ログインなしでグループを分ける：** 通信のたびにグループID（推測できないランダムな値）を送り、データベースの行単位の制限（RLS）で、そのグループのデータだけを読み書きできるようにしています
- **暗証番号：** 暗証番号はハッシュ化して保存し、アプリからは読めません。正しい番号を入れると端末ごとの合い鍵が発行され、書き込みはその合い鍵を持つ人だけができます。ログの「誰が」も合い鍵から記録するので、名前を名乗るだけではなりすませません
- **お金の計算：** 金額はすべて円の整数で扱い、小数の誤差が出ないようにしています。1件の支払いを分けた合計が、必ず支払い額と一致するように配分しています

## テスト

- 精算の計算：ランダムに作った2万グループ分で、合計のずれがないこと、送金リストどおりに払うと全員0円になることを確認
- データベース：PostgreSQLで、暗証番号・ロック・権限の制限を確認
- 画面：Chrome（スマホ幅）で、1人での操作、2人同時の操作、入力の復元、暗証番号、前払い金などを自動で操作して確認

## セットアップ（自分で動かす場合）

1. Supabaseでプロジェクトを作り、`supabase/` のSQLを番号順に実行する（`schema.sql` → `002` → … → `008`）
2. `config.js` に、自分のプロジェクトのURLと Publishable key を書く（`sb_secret_` で始まる鍵は書かない）
3. GitHubにアップロードし、Vercelでそのリポジトリを読み込んで公開する
4. `keepalive.yml` の接続先と鍵を、自分のプロジェクトのものに書き換える
